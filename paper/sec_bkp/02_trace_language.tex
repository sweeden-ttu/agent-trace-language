\section{Trace Language Model}
\label{sec:trace}

An agent $\mathcal{A}$ induces a \emph{trace language}
$L(\mathcal{A}) \subseteq \Sigma^*$ over a finite operation alphabet
$\Sigma$.  This section defines $\Sigma$, the trace, the trace
language, and the central theorem that a regular verifier preserves
the generator's Chomsky class.

\subsection{Operation alphabet}

\begin{definition}[Operation alphabet]
\label{def:opalpha}
An \emph{operation alphabet} is a finite, non-empty set $\Sigma$
whose elements $\sigma\in\Sigma$ each denote an effectful
computation \emph{name}, called an \emph{operation symbol}.
Each $\sigma$ is associated with a (possibly partial) computable
function $\llbracket\sigma\rrbracket : X \rightharpoonup Y$
acting on a state space $X$ and producing a successor state in
$Y\subseteq X$, so that the abstract symbol carries an effect when
executed.
\end{definition}

For the empirical instantiation, $\Sigma$ is the union of the column
entries of \texttt{trace\_language\allowbreak\_kaggle.csv}---operation
symbols such as
\texttt{load\_vector\allowbreak\_db(gemini\_embeddings\allowbreak .json)},
\texttt{invoke\_gemini\allowbreak (gemini-2.5\allowbreak -flash-lite)}, and
\texttt{train\_stacked\allowbreak \_ensemble(LGBM+XGB+HistGB\allowbreak +linear\_meta)}.

\subsection{Trace and trace language}

\begin{definition}[Trace]
\label{def:trace}
Let $\mathcal{A}$ be an agent with operation alphabet
$\Sigma_\mathcal{A} \subseteq \Sigma$, configuration space
$Q_\mathcal{A}$, initial configuration $q_0^\mathcal{A}$, step
relation $\delta_\mathcal{A}$, and halting set $F_\mathcal{A}$.
A \emph{run} of $\mathcal{A}$ on input $x$ is a sequence
\[
\rho = \bigl((q_0,\, w_0),\; (q_1,\, w_1),\; \dots,\; (q_n,\, w_n)\bigr)
\]
with $q_0 = q_0^\mathcal{A}$, $w_0 = \varepsilon$, and for each
$i\ge 1$, $\delta_\mathcal{A}(q_{i-1}, x) = (q_i, w_i)$ defined.
The run is \emph{accepting} if $q_n \in F_\mathcal{A}$ and the
halting verdict is accept.  The \emph{trace} of $\rho$ is the
concatenation
\[
\tau(\rho) \;=\; w_0 \cdot w_1 \cdots w_n \;\in\; \Sigma_\mathcal{A}^*.
\]
\end{definition}

\begin{definition}[Trace language]
\label{def:tracelang}
The \emph{trace language} of $\mathcal{A}$ is
\[
\begin{aligned}
L(\mathcal{A}) &=
\{\,\tau(\rho) : \rho \text{ is an accepting run of }
\mathcal{A} \text{ on some input } x\,\}\\
&\subseteq \Sigma_\mathcal{A}^*.
\end{aligned}
\]
\end{definition}

\begin{definition}[Trace equivalence]
\label{def:traceeq}
Two agents $\mathcal{A}_1, \mathcal{A}_2$ over a common alphabet
are \emph{trace-equivalent}, written
$\mathcal{A}_1 \equiv_\tau \mathcal{A}_2$, iff
$L(\mathcal{A}_1) = L(\mathcal{A}_2)$.
\end{definition}

\noindent An agent \emph{is} its trace language.  Trace-equivalent
agents are the same agent; internal architecture is irrelevant to
the identity criterion.

\subsection{Idealised versus bounded machines}

Every physical computation is bounded.  We adopt the standard
idealisation of Hartmanis and Stearns~\cite{hartmanis1965computational}:
analyse machines whose tape and time are unbounded in the formal
specification, while observing that any concrete execution witnesses
only a finite prefix.  For a Turing machine $M$, fix a tape bound
$b\in\mathbb{N}$ and time bound $t\in\mathbb{N}$.  The bounded
machine $M[b,t]$ is the restriction of $M$ to at most $b$ cells and
$t$ steps.

\begin{lemma}[Bounded soundness]
\label{lem:bounded-soundness}
If $M$ accepts $w$ in $\le t$ steps using $\le b$ cells, then
$M[b,t]$ accepts $w$.  Equivalently, every trace producible by the
bounded machine is producible by the idealised machine $M$.
\end{lemma}

This lemma is the formal warrant for treating the Goal-Driven agent,
as implemented on a finite laptop, as an idealised Type-0 envelope
for analysis.  Any trace the bounded machine emits is also emitted
by the idealised machine, and verification claims discharged against
the idealised machine apply a fortiori to the bounded one.

\subsection{CSV files as trace languages}

The header row of \texttt{trace\_language\_kaggle.csv} names the
sub-agents $\mathcal{A}_1,\dots,\mathcal{A}_{13}$.  For each $i$,
the $i$-th column (skipping empty cells) is a single trace
$\tau_i \in \Sigma_{\mathcal{A}_i}^*$, one accepting run on the
\textsc{Spaceship Titanic} input.  The trace language
$L(\mathcal{A}_i)$ contains, in principle, infinitely many strings;
the column records the one the recursive enumeration emitted.
The same correspondence holds for
\texttt{trace\_language\_original.csv} (twelve columns, no
\texttt{kaggle\_trainer}).

\subsection{Closure under intersection with a regular verifier}

The following theorem is the architectural pivot.  Its proof is
standard~\cite{hopcroft2006automata}: each Chomsky class is closed
under intersection with a regular language.

\begin{theorem}[Regular conformance closure]
\label{thm:closure}
Let $\mathcal{G}$ be a generator whose trace language
$L(\mathcal{G})$ is in Chomsky class $\mathcal{L}_i$ for some
$i\in\{0,1,2,3\}$.  Let $\mathcal{V}$ be a verifier with
$L(\mathcal{V}) \in \mathcal{L}_3$ (regular).  Define the
\emph{validated composition} $\mathcal{G}\,\Vert\,\mathcal{V}$ as
the trace filter whose accepted traces are exactly those emitted by
$\mathcal{G}$ and accepted by $\mathcal{V}$'s DFA.  Then
\[
L(\mathcal{G}\,\Vert\,\mathcal{V})
\;=\; L(\mathcal{G}) \cap L(\mathcal{V})
\;\in\; \mathcal{L}_i.
\]
Regular conformance filtering does not raise the Chomsky class of
the producer language.
\end{theorem}

\begin{proof}[Sketch]
Each Chomsky class $\mathcal{L}_i$ is closed under intersection with
regular languages: for $i=3$ by the product
construction~\cite{rabin1959finite}, for $i=2$ by the product of a
PDA with a DFA~\cite{hopcroft2006automata}, for $i=1$ by LBA
closure, and for $i=0$ by the product of a Turing machine with a
DFA~\cite{turing1936computable}.
\qed
\end{proof}

\begin{corollary}[Verifier-side budget]
\label{cor:budget}
Given a candidate trace $\tau$ of length $n$, checking verifier
conformance $\tau \in L(\mathcal{V})$ runs in $O(n)$ time and
$O(1)$ space on the verifier side.  Full membership in
$L(\mathcal{G})\cap L(\mathcal{V})$ may remain undecidable when the
producer is modelled under a Type-0 abstraction.
\end{corollary}
